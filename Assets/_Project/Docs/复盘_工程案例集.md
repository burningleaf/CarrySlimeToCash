## 1. 技术债与已知问题（原 §4）

### 4.1 ✅ 已解决：收益公式统一（原"两套时间奖励公式冲突"）

已定案并实现，详见 `定案_收益公式与调参基准.md`：

- **公式（第二版，已实现）**：`收益 = 售价 + Σ金币`，其中 `售价 = 满格 × 血条剩余%`。
  **血条 = 售价条**，史莱姆随时间掉血（每秒掉 5 元），时间惩罚从"抽象倍率"变成"**体内的血量**"。
  参数极简：全局 3 个常数 + **每关只填 `parTime`**，其余全部算出来。
- **整数化**：`parTime` 取 10 的倍数 → `满格 = 10 × parTime`，于是
  **1 秒 = 5 元 · 1 点血 = 5 元 · 1 枚金币 = 2 秒绕路预算**，全是整数，能心算。
- **星级**：相对基准的百分比 `{0.6, 0.9, 1.1}` —— 原来 3 星（门槛 180 > 理论上限 150）**永远拿不到**
- **规则**：时间不会饿死史莱姆（掉到 25% 停住），**危险会**（可打到 0 死亡）
- **真相源**：`parTime` 在 `LevelData.meta`，全局常数是 `LevelManager` 的 `static` 字段
- **工具**：菜单 **⓪-5 收益公式自检** 打出完整数值表

实测：Level2（金币 100）冲刺 vs 全收集 **差 17%** ✅ 落在目标区间；
Level1（金币 20）**20 秒不捡币就能拿 3 星**，金币毫无意义。

### 4.7 ✅ 已解决：导出器"漏读字段"会让数据悄悄丢失（踩了三次）

这是一类**极其隐蔽**的 bug，值得单独记一笔：

> `LevelBuilder` 把数据写进组件，`ExportScene` 再把组件读回数据。
> **只要有一边漏了字段，下一次导出就会把它重置成代码默认值——而且往返检查会显示"一致"。**

因为往返检查只验证"重建前后自洽"，证明不了"导出器没漏字段"。

踩到的三次：

| 字段 | 后果 |
|---|---|
| 壁画 `murals` | 导出器完全不认识路牌 → 第一次往返就把 **15 块路牌从数据和场景里一起抹掉**了 |
| `meta.parTime` | 没读回来 → 教程关的 **80 秒被重置成代码默认的 50 秒** |
| `meta.levelIndex` | 被 `SlimeDemoSetup.IsRepairableInt` 当成"0 = 没配置"自动补成了 1（教程关的合法值就是 0） |

**两道防线**：

1. `BatchRoundTripAll` 新增检查：**磁盘上的 JSON 与"从场景导出的结果"逐行比对**，不一致就报 `⚠ 导出器可能漏读了字段` 并列出差异（第 1、2 次就是它抓出来的）
2. `IsRepairableInt` 里只保留"0 真的等于没配置"的字段（`slimelayer` / `carriedlayer`），
   移除了 `levelindex` / `baseprice` / `maxwaypoints` / `currenthealth`

#### ★ 第四次（2026-09-23 收尾复盘实测）：不是"漏读字段"，是"**追加的数据被反向覆盖**"

前三次是"字段被重置成默认值"，这一次是"**整条条目被删掉**"，而且**一次删掉 5 条**。

| 被吃掉的东西 | 后果 |

## 2. 求解器：算法、模型与自检（原 §5.5 的详细部分）

**代码**：`Assets/_Project/Editor/LevelSolver.cs`（**只在 Editor 里，不进包**）。
菜单 `Tools → 呆呆史莱姆 → ◇◇-1 求解器自检` / `◇◇ 求解当前关卡`；命令行入口 `LevelSolver.BatchSolveAll`、`LevelSolver.BatchSolverSelfTest`。

### 它算什么

| 输出 | 含义 |
|---|---|
| 可达性 | 起点 → 终点走不走得通；走不通就是关卡有断点 |
| 最短时间 + 直线下界自检 | 求解结果必须 ≥ 水平距离 ÷ 移速，不满足就是求解器算错了 |
| 逐动作路线明细 | `0.64s 落 Ground_D(x92@y0) → PitFloor(x92@y-6)`，每一步都能肉眼核对 |
| 金币取舍 | 每枚金币的**绕路代价** vs 预算（面值 ÷ 5 元/秒），直接给出"值得捡 / 不划算" |
| 冲刺 / 贪心全拿 R̄ / **最优解 R\*** | 三行对照 + **收益差 = (R\* ÷ 冲刺总分) − 1**，用来验收"15%~35%"调参判据。R\* = 掩码枚举出来的**精确最优**（玩家最多能赚多少）；旧的"全收集"降级成对照行 R̄，并标"非最优"（它把陷阱金币、甚至求解器拿不到的币也算了进去） |
| 逃课 / 装饰障碍检测 | 逐个障碍移除后重算，看它是必经障碍、真障碍，还是装饰品 |
| 净空检查 | 头顶净空 < 玩家碰撞盒高（1.0）的路段 —— 面模型看不见的坑 |

### 模型是什么（以及为什么不用网格 A\*）

节点 = **可站立面上的"站点"**（段两端 + 出生点 / 终点 / 每枚金币的 x + 与所有邻段的"最接近点"），
边 = 走 / 跳 / 落，费用 = 真实耗时（走 = Δx ÷ 移速，跳 = 起跳到顶点 + 顶点落到目标，落 = √(2h/g)）。
**不是**格子 A\*，**不是** NavMesh —— 遵守"禁止寻路 / A\* / NavMesh"的约束，也让结果能与手算对上。

> **为什么不是"每段一个节点"**：段内走路会变成免费，一条 92 格长的地面等于瞬移，报出 7 秒（实际 24 秒）。
> **为什么不是"每段两端两个节点"**：起跳被绑死在端点，竖井里嵌在坑底的台阶（dx=0 垂直跳）永远连不上，报"不可达"。
> 站点法两个问题都解决，而且能顺带算出"金币绕路代价"。

### 自检抓出来的 4 个真 bug（都会让报告"看着合理但是错的"）

1. **掉落被按跳计价**：连了"跳"边就 `continue`，跳过"落"边。从地面掉进 6 格深的井：掉落 0.64s 被算成 1.23s。结果求解器宁可爬柱子绕路，也不肯直接走进坑里 —— 报出的路线完全是错的。
2. **立在地上的墙不存在**：相邻地面合并成一整段，立在中间的墙不会切断它 → 模型认为玩家能**穿墙走过去**（T4 抽掉台阶后依然"可达"就是它）。
3. **反向图不同步**：发现更便宜的边时只更新了正向图，`toGoal`（金币绕路 = 过去 + 回来）一直用旧的贵价 → **柱顶金币的绕路代价正好翻倍**（回来的"掉落 0.43s"被"跳下来 0.89s"盖住）。
4. **障碍判定逻辑写反一半**：原来只看"是否变慢 / 不可达"，但移除**墙**会让路线**变快**（抄近路）→ 真障碍被误报成装饰品。现在 |Δ| 大就算有用，方向只决定它是"落脚点"还是"障碍"。

| # | 机关 | 用法 | 考的是 |
|---|---|---|---|
| ① | 压力板 A → 门 1 | 踩一下就把门**永久**打开（`oneShot` 锁定） | 联动 + 一次性语义 |

这正是"让玩家自己发现规则"的无文字教学。

### 联动验收（59 项全过）

无头验收的难点：**批处理模式进不了 Play 模式**（实测探针跑 400 秒没完成），而"联动"是运行时行为。
解决办法是自己搭一个无头游戏循环：

```
Physics2D.Simulate(1/60)  →  反射补发 OnTrigger/OnCollision  →  反射调用所有脚本的 FixedUpdate / Update
```

用的是**真实的游戏脚本、真实的碰撞体、真实的物理**，只是帧由测试来推。两个已知的妥协，都在报告里标了：

| 妥协 | 原因 | 怎么补 |
|---|---|---|
| 编辑模式下 `Awake` / `Start` 不会被调用 | Unity 只在运行时调 | 测试显式补调一次（不补的话平台"活着但不动"、敌人原地抽搐） |
| 编辑模式下 `Time.time` 不走、物理回调不派发 | 主循环不跑 | 事件的**真实 Collider** 由测试交给产品的处理函数；与时间有关的行为（路点等待、压板松手容差）显式模拟，并在报告里注明 |

碰撞矩阵是**单独解码验证**过的（逐位核对 `Physics2DSettings.asset`），所以真实运行时事件派发没问题。

### 第 4 步抓出来的 2 个真 bug

1. **移动平台的路点被挂成了平台的子物体** —— 路点跟着平台一起跑，平台永远追不上自己的目标点，会**一路飞出去停不下来**。
   实测：本该停在 x33，实际飞到 x43 还在跑。修法：路点挂到平台的**父节点**上，位置固定在世界坐标。
   （`LevelBuilder.BuildMovingPlatform`）
2. **压力板的默认触发掩码把移动平台过滤掉了** —— `plateTriggerMask` 只认 `Player|Slime|CarriedSlime`，
   而碰撞矩阵里 `MovingPlatform × TriggerZone` 明明是开的。于是"平台压板"这种经典时序机关**永远触发不了**。
   修法：默认掩码加上 `MovingPlatform` 和 `Enemy`（`PressurePlate` 的注释本来就写着"玩家/史莱姆/怪物/移动平台压住即激活"）。
   现有三关一个压力板都没有，所以这个改动对它们是零影响。

### 顺带查清的碰撞矩阵（`Physics2DSettings.asset` 逐位解码）

| 关键结论 | 值 |
|---|---|
| 玩家 ↔ 敌人 / 门 / 移动平台 / 触发区 | 全部**开** ✅ |
| 史莱姆 ↔ 敌人 / 门 / 移动平台 | 全部**开** ✅ |
| 携带中的史莱姆 ↔ 敌人 | **关**（抱着的史莱姆免疫伤害，双保险） |
| 玩家 ↔ 拾取物 | **关** —— **只有史莱姆能捡金币**。这是故意的，不是 bug |
| 门 ↔ 地面 / 平台 | **关** → 门必须是静态的，不能给它加刚体 |
| 移动平台 ↔ 地面 | **关** → 平台穿地形走，靠 `MovePosition` |
| 默认层 / UI 层 | 和**任何层都不碰** —— 新物体忘改层就会静默穿地掉下去 ⚠ |

## 7. 真 bug 复盘故事（原 §7 的 ★ 部分）

### 7.1 ★ 史莱姆"卡住挣扎"（把 bug 变成角色性格）

**现象**：玩家跳上台子，史莱姆跟跳没跟上，落在台子侧面 / 坑边**卡住不动**，要回去举起来才能脱离。

**根因链**（`SlimeController`）：

```
它只在玩家跳的时候才跳（CheckJumpFollow）
  → 玩家站上台子后一动不动，它就再也不会跳
  → 而 CheckBlocked 探到前方是高墙 / 无底坑 → StopHorizontal() → 永久卡住
  → 口哨召回也走同一个 MoveTowards → 同样卡住
```

**唯一的救援是"玩家再跳一次"**（阻塞分支里就调了 `CheckJumpFollow()`）。这个设计其实是自洽的，只是缺了"我卡住了"的表达。

**做法**：不消掉这个状态，而是给它加一段**程序化挣扎动画**（项目里没有动画资源，所以全部用代码做，**只动贴图、不动碰撞体，绝不影响玩法**）：

| 效果 | 参数 | 说明 |
|---|---|---|
| **高频左右颤动** | `struggleShakeAmplitude` **0.12** / `struggleShakeSpeed` 42 | "用力到发抖"（第一版 0.06 太不明显，已加倍） |
| **使劲时横向压扁、纵向压低** | `struggleSquashX` **0.22** / `struggleSquashY` **0.18** | 贴着台子推的感觉 |
| **小幅上顶** | `struggleHopHeight` **0.14** / `struggleHopSpeed` 7 | 像在试着蹦上去 |
| **★ 变色** | `struggleColor` 暖红 / `struggleColorSpeed` 7 | **光靠抖动远看不够明显**，加一层脉冲染色；喘气时淡回白色。优先级：受伤闪红 > 挣扎变色 > 正常白 |
| **挣扎 → 喘气 循环** | `strugglePantPeriod` 2.6s / `strugglePantDuration` 0.5s | 顶一会儿没劲了缩一下，再顶 —— "呆呆的但很努力" |
| 判定延迟 | `struggleDelay` 0.25s | 连续被挡住 0.25 秒才开始挣扎，避免蹭一下就抖 |

全部是 `public` 字段，走查后想调力度直接改数值。

> 以后有动画资源了，把 `writeAnimatorStruggleParam` 打开、给 Animator 加一个 `IsStruggling` 参数，就能接真正的动画。

### 7.2 ★ 顺带查出的真 bug：深坑 4 格太宽，史莱姆必掉

日志里刷了一屏：

```
[SlimeController] 史莱姆掉出了地图，已送回最后一次站稳的位置 (13.51, 0.45)
```

`_lastSafePosition` 是 13.51 而坑在 16→20 → 说明它**在 13.5 就起跳了**。原因是：

```
史莱姆跟在玩家身后约 1.4 格，跳距只有 5.85
能跨过的最大坑宽 = 5.85 − 1.4 − 玩家提前起跳的距离

坑宽 4   → 玩家必须在离边缘 0.45 格内起跳（几乎不可能）→ 史莱姆必掉
坑宽 3   → 容差 1.45 格 ✓
```

掉坑后 `HandleOutOfWorld` 会把它送回坑边（**不会丢**），但边缘检测让它停下 —— **这正是"卡在角落"的真正来源**。

**已把坑宽改成 3 格。** 携带跳 2.45 仍然跨不过去，"强制放下史莱姆"的设计意图不变 ✓

### 7.3 ★ 深坑改成"直接失败"（不再是送回）

**改之前**：掉出地图 → `HandleOutOfWorld` / `playerDeathFallY` → **送回最后一个安全位置**，继续玩。
**改之后**：深坑底部放一块**看不见的死亡判定块**，碰到就**直接关卡失败**，重开本关。

| 做法 | 说明 |
|---|---|
| **死亡判定块** | 一条横跨全关的 `Hazard`（x −2→212，y **−16→−13**），参数 `伤害 999 / killPlayer / fatalToPlayer`。**从哪个坑掉下去都会碰到**，不会无限往下掉 |
| **玩家** | `Hazard.fatalToPlayer = true` → 新增 `LevelManager.OnPlayerFellIntoPit()` → **直接失败**，不给复活 |
| **史莱姆** | 伤害 999 一下就死 → `OnSlimeDied()` → 失败 |
| **看不见** | 相机的 `camMinY` 从 −14 收到 **−4**：竖井底（−6）仍然看得见（画面最低到 −10.5），但掉坑的人不会带着相机一路追到判定块上 |
| **统一失败出口** | 新增 `LevelManager.FailLevel()`，史莱姆死亡和玩家掉坑都走它，保证"失败"只有一种表现 |
| **结算文字** | 新增 `LevelFailReason` 枚举 + `LevelResult.pitFailStampText`，玩家掉坑显示"掉进深坑了…"而不是"史莱姆阵亡…" |

新增字段全部是 `public` 且**默认值不改变原有行为**（`fatalToPlayer` 默认 `false`）；
`Level0` / `Level2` 没有无底深坑，**这一版只改了 Level1**。

> **先不摆检查点了**（Level1 里已移除）。理由：现在"掉坑"和"史莱姆死"都是直接失败，
> 而游戏里没有别的会杀死玩家的东西（水不杀、尖刺已移除、敌人还没放），
> 所以检查点亮了却不起任何作用 —— 与其误导玩家，不如先不摆。
> 机制和脚本（`Checkpoint.cs`）都留着，**第 4 步放尖刺 / 敌人时再启用**：
> 那些用 `killPlayer = true` 但 `fatalToPlayer = false`，碰到只扣一条命、回检查点继续。

### 7.4 ★ 相机不跟踪的 bug（也是我上一步改出来的）

**症状**：往竖井下方走时，相机不跟着下去，**看不见地图**。

**根因**：`CameraFollow.ClampToBounds` 里 bounds 的语义是「**相机视野必须待在这个矩形里**」，
不是「相机中心的活动范围」：

```csharp
float minY = boundsMin.y + halfHeight;   // halfHeight = orthographicSize = 6.5
position.y = Mathf.Clamp(position.y, minY, maxY);
```

我上一步为了"别让相机追到死亡判定块上"，把 `camMinY` 从 −14 改成了 **−4**
→ 相机中心被夹到 `[−4 + 6.5, …] = [2.5, …]`，**永远下不到 2.5 以下**。
玩家下井到 −6，画面却只到 −4 → 人完全在屏幕外。

**正确算法**（要让相机中心跟到 −4.5，即玩家在井底 −6 时 + offset 1.5）：

```
camMinY ≤ −4.5 − 6.5 = −11      ← 相机中心才能到 −4.5
camMinY = −11 时画面最低 = −4.5 − 6.5 = −11
死亡判定块在 −13 → 仍在屏幕外 ✓
```

**已改成 `camMinY = −11`、`camMaxY = 16`。**
以后调相机边界记住：**写进去的是"视野范围"，相机中心会被自动内缩一个半屏。**

### 7.5 ★ 挣扎动画看不到 —— 四个真根因（一层比一层深）

**第 1 层：判定根本没触发。**
`MoveTowards` 里有一条提前返回：
```csharp
if (distance <= stopDistance) { StopHorizontal(); CheckJumpFollow(); return; }   // ← 在这儿就 return 了
// 后面的 if (IsGrounded && CheckBlocked(dir)) { _blockedThisFrame = true; ... } 根本走不到
```
史莱姆卡在台子底下、玩家站在台上时，水平距离早就 ≤ `followDistance`(1.4)，
它走的是"到点了，停下"，永远走不到 `CheckBlocked`。
**修法**：补一条独立判定 `IsStrandedBelowPlayer()` —— 贴地 + 没在横向移动 + 玩家高出 >1.2 + 水平差 ≤2.2。

**第 2 层：表现层压根没跑。**
```
Slime.prefab：  spriteRoot: {fileID: 0}   spriteRenderer: {fileID: 0}   ← 都是空
Level1.unity：  spriteRenderer 有覆盖，spriteRoot 没有覆盖 → 运行时为 null
```
而 `UpdateWobble` / `UpdateFlash` 开头都是 null 早退。**所以蠕动、挣扎抖动、受伤闪红、
被举着时的晃动、玩家转身翻转 —— 全部从来没生效过，而且一句报错都没有。**
**修法**：照 `body` 的自愈写法在 `Awake` 里兜底：
```csharp
if (spriteRenderer == null) spriteRenderer = GetComponentInChildren<SpriteRenderer>(true);
if (spriteRoot == null && spriteRenderer != null && spriteRenderer.transform != transform)
    spriteRoot = spriteRenderer.transform;   // != transform：绝不能把碰撞体也一起晃
```

**第 3 层：判定在闪，计时永远攒不满。**（靠诊断日志定出来的）
```
[史莱姆卡住] 状态=Follow 贴地=True 被墙挡=False 玩家在上方=True 挣扎=False
             我=(164.9,5.5) 玩家=(163.6,6.8) timeScale=1.00
```
`stranded=True` 但 `挣扎=False` → `_blockedTimer` 攒不到 0.25 秒。
原因：玩家在头顶跳来跳去，玩家 y 一直在变 → `dy` 在 1.2 阈值上下反复穿越
→ 判定一帧真一帧假 → 每次"假"都走 `else` **把计时清零** → 永远攒不满。

**修法**：改成**充能表**（涨得快、掉得慢），彻底免疫抖动：
```csharp
_stuckness = Mathf.MoveTowards(_stuckness, 卡住 ? 1f : 0f,
                               dt / (卡住 ? struggleDelay : struggleReleaseDelay));
_struggling = _stuckness >= 1f;      // struggleReleaseDelay(0.6) > struggleDelay(0.25)
```

**第 4 层：`stranded` 判据两个方向都错**（靠用户反馈第二次定出来）

```
用户反馈：史莱姆没卡住时日志狂刷（误报）；真卡在台子角上时反而不报（漏报）
```

| 方向 | 原因 |
|---|---|
| **误报** | 判据是"玩家高出 >1.2 + 水平差 ≤2.2"。**正常跟跳**（跳上柱子 / 跳上台子）时这两个条件也成立 → 每次跟跳都命中 |
| **漏报** | 判据第一行是 `if (!IsGrounded) return false;`。史莱姆**悬在台子角上**时 `groundCheck` 探不到地面 → `IsGrounded=false` → 直接被排除 |

**修法：换成一个不关心"为什么卡"的判据** ——

```csharp
// 处于跟随/召回 + 2D 距离还远（> followDistance + 0.6）+ 一个物理步几乎没移动（< 0.03）
private bool IsStuckNow(float movedThisStep) { ... }
```

移动距离由 `Vector2.Distance(transform.position, _prevStepPos)` 在每个 FixedUpdate 开头量出来
（正常跟随一步约 0.13 格，卡住时 ≈0）。**只要是"想过去却过不去"就算，不管拦路的是高墙、
台子角、无底坑还是悬空边**，所以两个方向都不会错。

配套：`struggleDelay` 从 0.25 提到 **0.8 秒**（比跟跳的正常反应时间长，避免每次跟跳闪一下）；
日志改成**只在真正进入挣扎时**打印，不再刷屏。

> **四层叠加**：判定没触发 → 表现层是空的 → 计时被抖掉 → 判据本身两个方向都错。
> 每一层单独看都"没报错、看着正常"，**只有日志能一次穿透**。

### 7.6 ★ 玩家"不能跳跃"的 bug —— 前两个假设都错了

| 版本 | 假设 | 结果 |
|---|---|---|
| 第一版 | 玩家踩在史莱姆头上，而 `Slime` 层不在 `groundLayer` 里 → 不算着地 | ❌ **假设错误**。把 `Physics2DSettings.asset` 的 `m_LayerCollisionMatrix` 按字节反转解出来：`Player` 行 = `0x0001be00` → 只与 Ground/Platform/MovingPlatform/Hazard/Enemy/TriggerZone/Gate 碰撞，**Player↔Slime 是关的**，玩家根本踩不到史莱姆头上 |
| 第二版 | 把 `Slime` 层加进 `groundLayer` 兜底 | ❌ **改动无效**。写成了 `if (groundLayer.value == 0) {...}`，而场景里这个掩码早就配好了，**分支永远不会执行** |

**现在改成无条件 OR**（`treatSlimeAsGround`，默认开），并在 `Awake` 里加了注释说明为什么不能写"掩码为 0 才兜底"。
这是防御性修复，**大概率不是这次的病因**。

**真病因还没确定**，所以加了**诊断日志**（`logJumpFailures`，默认开）：
按了跳跃却跳不起来时打一行

```
[跳跃失败] 贴地=? 距上次着地=?s(宽限0.10) 可操控=? 死亡=? timeScale=? 速度=(?,?) 位置=(?,?)
```

这一行能直接区分三种可能：

| 日志特征 | 说明 |
|---|---|
| **`timeScale=0.00`** | **游戏被暂停了**。`PauseMenu` 按 Esc 会把 `Time.timeScale` 设 0；如果暂停面板没显示出来，现象就是"整个人卡住 + 不能跳 + 史莱姆动画也不动"——**这个假设同时能解释两个症状，优先级最高** |
| `可操控=False` | 玩家控制被关了（关卡失败 / 通关演出） |
| `贴地=False` 且距上次着地 > 0.10 | 地面检测失效（真·站在地上却判定不在地面） |

> ⏳ **2026-09-23 夜 补（这条的后续）**：`06_问题.md` **#28** 给出了同一区域的一个真 bug ——
> 空手 / 抱着史莱姆都能**无限空中跳**：`groundLayer` 曾**无条件**把 `Slime` / `CarriedSlime` 并进"起跳判据"。
> **修法已按定案改成两个掩码**：`groundLayer` 只留 `Ground|Platform|MovingPlatform`（起跳判据），
> 史莱姆那两层只进 `slimeStandLayer`（站立表现）；**无限空中跳改由物品「跳跃云朵瓶」赋予**（占第 4 格 / 无限次 / 拿着它时不能举史莱姆）。
> 改动已落地，**属"进行中"：待跑 Unity 侧验证**。

### 7.7 ★ 跳跃手感修复（这一版一起改了）

用户反馈"跳跃一顿一顿的"。诊断出**两个真原因 + 一个被排除**：

| 原因 | 原来的行为 | 改成 |
|---|---|---|
| **1. `jumpCutMultiplier = 0.5` 没有最短按住时间** | 轻点一下只能跳 **0.75 格**，按满是 **3.0 格** —— 同一个键高度差 4 倍，纯看你按多久 | 新增 `minJumpHoldTime = 0.08`（起跳后 0.08 秒内不截断）+ 截断比例放宽到 **0.65**。轻点也能拿到约 **1.8 格**，高度范围收到 [1.8, 3.0] |
| **2. `CheckWallAhead` 命中时把水平速度归零** | 跳跃时擦到**任何台阶侧面**，横向速度瞬间清零 → **这就是"一顿"** | 改成 `newX = body.velocity.x`：**只停止加速，保留惯性**。既不粘墙也不卡顿 |
| 3. 碰撞检测是 Discrete | — | **本来就已是 Continuous**（我多加了一行重复代码，已清掉）。改成可开关字段 `useContinuousCollision` |

附带：`maxFallSpeed` 25 → **18**（原来每物理步走 0.5 格，容易落点漂移，相机也跟不上）。

**这四条全是 `public` 字段**，走查后想继续调直接改数值即可，不用动代码。

- 「跑完才 30 秒」→ 调关卡长度或障碍密度
- 「根本不想捡金币」→ 调金币面值或位置
